# IVF v0.1.0-rc2

Release candidate. Not a stable release. See the limitations at the end for what still
has to happen before `v0.1.0`.

`v0.1.0-rc1` remains immutable and was not moved, deleted, or recreated.

## External-audit remediation

An independent audit of `v0.1.0-rc1` returned "keep as rc1" with six load-bearing
findings. Every one was reproduced against the tag before anything changed. The record,
including the exact command that reproduced each finding, is in
[`docs/audits/v0.1.0-rc1-remediation.md`](../audits/v0.1.0-rc1-remediation.md).

## Unit and frame contract enforcement

Unit, frame, dtype, and tolerance-unit compatibility are now checked automatically for
every signal an oracle consumes, with no manifest opt-in. On rc1 a candidate declaring
`pole_angle` in degrees against a baseline in radians returned `PASS` and exit `0`. It now
returns `INVALID_EXPERIMENT` and no oracle runs at all. A signal declaring more than one
physical unit is refused when an oracle would reduce it to a single scalar against a
single threshold. A missing declaration is `unverifiable`, never "matched".

New reason codes: `IVF-CONTROL-SIGNAL-UNIT-MISMATCH`, `IVF-CONTROL-SIGNAL-FRAME-MISMATCH`,
`IVF-CONTROL-SIGNAL-DTYPE-MISMATCH`, `IVF-CONTROL-TOLERANCE-UNIT-MISMATCH`,
`IVF-CONTROL-MIXED-UNIT-REDUCTION-INVALID`.

## Source-bundle digest binding

Loading a strict bundle now records its finalized checksum root, payload digest, capture
id, creation time, and producer, and writes them into sealed provenance under
`subject_identities`. A verdict names the inputs it judged rather than only the paths they
occupied. `trajectory_bundle/v1` gained an optional additive `capture` block.

## Explicit identity-check mode

Identical subject content is refused by default with `IVF-EXPERIMENT-SELF-COMPARISON`.
An intentional A/A run is still available, but it must be declared with
`experiment_mode: identity_check`, and the report then states that the run measures
validator identity behaviour rather than independent repeatability or equivalence.

## Corrected-case role change

The rc1 corrected case was described as a fresh independent capture with the defect
removed, and as the primary negative control. Its payload was byte-identical to the
baseline and its capture spec differed only in the output name, so there was no defect to
remove. Two independent simulator processes reproduced the payload bit for bit.

The case is now a declared A/A identity check and an independent no-defect repeatability
check. The **benign-difference case is the primary engineering negative control**, because
it is the one carrying a real configuration change and a real nonzero accepted divergence.
The same correction was applied to the synthetic `synthetic_fixed.yaml` case study.

## Evidence-seal threat model

"Tamper-evident" overstated an unkeyed digest. The wording is now consistent across the
README, evidence schema, claims table, CLI help, `ivf reproduce` output, and the rendered
report:

> IVF evidence bundles include checksums and an integrity seal that detect accidental
> corruption, incomplete transfer, and uncoordinated modification. The seal is not a
> digital signature and does not establish authenticity against an actor who can modify
> and reseal the entire bundle.

No signing infrastructure was added. A test asserts the boundary, including that a
coordinated edit plus reseal verifies as internally consistent.

## Typed reproduce errors

Exit code `1` is reserved for a scientific `FAIL`. Expected operational failures, a
missing path, unreadable or malformed evidence, a checksum mismatch, an unknown evidence
schema, a manifest error, or an ordinary `OSError`, now return `ERROR` with a stable reason
code and exit `5`. Output is one actionable line; `--debug` restores the traceback.

## Publicly recomputable equivalence record

`tools/recompute_release_equivalence.py` recomputes every public aggregate from a clean
clone, with the selection, ordering, encoding, and concatenation format stated:

```bash
git worktree add /tmp/rc1 v0.1.0-rc1
python tools/recompute_release_equivalence.py --check --root /tmp/rc1
```

Claims that depend on unpublished history are labelled `author_attested`. Object ids that
no reader could resolve were removed rather than kept as decoration.

## Gated public simulator CI

The workflow carries a self-hosted GPU job that is gated on the repository variable
`IVF_GPU_RUNNER`. Both modes are now publicly exercised:

* **unset**: the workflow parses, CPU and offline jobs run, and the simulator job is
  visibly skipped. A CPU step asserts the simulator tests skip rather than pass, and
  prints that a green CPU job is not evidence about the simulator.
* **set**: the job runs on a self-hosted GPU runner with `IVF_REQUIRE_SIMULATOR=1`, so a
  missing Isaac install fails the job instead of skipping it. Fresh captures run against
  a real Isaac Sim 6.0.0.1 / Isaac Lab 10.2.0 / physx 2.8.1 / newton 1.7.0 install, with
  5 PhysX tests and 1 Newton test passing.

The job never runs from a `pull_request` event. This repository is public and the runner
is self-hosted, so a fork pull request reaching it would be arbitrary code execution on
the machine holding the Isaac installation.

## Unchanged scientific finding

Every tolerance value is byte-identical to `v0.1.0-rc1`. The PhysX-versus-Newton
comparison remains an intentional `FAIL` and was not tuned:

| Metric | Value | Budget |
|---|---|---|
| pole angle divergence | 3.533 rad, first violation step 29 | 0.0288 rad |
| pole velocity divergence | 12.99 rad/s, first violation step 13 | 0.0909 rad/s |
| termination timing delta | 2 steps | 1 step |
| mean paired shift | -0.1862 rad, CI [-0.1877, -0.1848] | +/- 0.0144 rad |
| decision agreement | 1.0 | 1.0 |

No claim is made about which backend is physically correct.

## Breaking changes

- an undeclared self-comparison returns `INVALID_EXPERIMENT` instead of `PASS`;
- dimensionally incompatible signals return `INVALID_EXPERIMENT` instead of `PASS`;
- `ivf reproduce` infrastructure failures exit `5` instead of `1`;
- the strict capture contract requires `hardware` and `seed.env_order`, and rejects
  `unknown` units and frames.

## Limitations

- Unit comparison is string equality after normalization, not dimensional algebra. `m` and
  `cm` are refused rather than converted, and a unit declared wrongly but consistently on
  both sides is not detectable from the data.
- Content identity is computed over the arrays, so an independent deterministic
  re-execution is indistinguishable from a copy by construction.
- Determinism was observed on one machine. No cross-machine determinism is claimed.
- The simulator job has been exercised on one self-hosted runner. No claim is made that
  the GPU path works on arbitrary hardware.
- Statements labelled `author_attested` remain unverifiable by anyone but the author.
